= Module 01: Guided tour — exporting Model Catalog data as CSV
:navtitle: Module 01: Guided tour — CSV export

In this module you will take a guided tour of *CSV export for Model Catalog data*, a Developer
Preview capability in Red Hat OpenShift AI 3.5. You can export model catalog metadata to CSV
format by using a standalone Python CLI script. The script queries the Model Catalog REST API,
paginates through the full result set, and produces an RFC 4180-compliant CSV file that includes
all model metadata and custom properties.

IMPORTANT: This is a guided tour of a Developer Preview feature, so the module is descriptive: you
observe the data the export reads, run the documented export script, and inspect the resulting CSV.
The script installation, authentication, and full usage reference are covered in the *CSV Exporter
for Model Catalog* guide linked from the
https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/release_notes/index[RHOAI 3.5 release notes].

**Learning objectives:**

* Explain what CSV export for Model Catalog data does and where it fits in the model catalog workflow
* Locate the Model Catalog in the OpenShift AI dashboard and identify the metadata you can export
* Run the export script with its documented options and validate the RFC 4180 CSV output

== Exercise 1: Locate the metadata you will export

The model catalog is the source of the data the export script reads. Before exporting, familiarize
yourself with what the catalog contains and where it lives.

.Model catalog in the RHOAI dashboard

Data scientists and AI engineers use the model catalog to discover and evaluate the gen AI models
that are available and ready for their organization to register, deploy, and customize. The catalog
provides models from different providers that you can search, discover, and evaluate before you
register models in a model registry and deploy them to a model serving runtime.

.Procedure

. Navigate to link:{openshift_console_url}[the OpenShift AI console,window=blank] and log in.
. From the OpenShift AI dashboard, click *AI hub → Models → Catalog*.
+
The Catalog page displays a high-level view of available models, including the model category,
name, description, and labels such as task, license, and provider. Third-party validated models
also show performance benchmark data.
. In the menu bar, browse the model categories: *All models*, *Red Hat AI models*,
*Red Hat AI validated models*, and any custom categories your administrator configured.
. Use the search bar to find a model by name, description, or provider, and use the filter menu to
narrow results by task, provider, license, language, or tensor type.
. Click a model name to open the model details page and note the model description, the model card
information supplied by the provider, and the key model properties shown in the *Model details*
section.

Each model entry in the catalog carries metadata — description, provider, labels, model card
information, and performance metrics for validated models — plus any custom properties. All of
this is the data the CSV export packages.

image::01-model-catalog-page.png[Model catalog page in the AI hub,link=self,window=blank,width=700]

=== Verify

You are viewing the Catalog page under *AI hub → Models* in the OpenShift AI dashboard, and you can
see at least one category of models with their names, descriptions, and labels. If the catalog is
empty, ask your administrator to check the configured model catalog sources.

Now that you know what the catalog holds, run the export script against it.

== Exercise 2: Run the CSV export script

The export capability ships as a standalone Python CLI script that requires Python 3.10+ with no
additional dependencies. The script queries the Model Catalog REST API, paginates through the full
result set, and writes an RFC 4180-compliant CSV file that includes all model metadata and custom
properties. Writes are atomic, so a failed run never leaves a partial CSV behind.

NOTE: The export script is `model_catalog_export.py` in the Model Registry project's
`tools/csv-exporter` directory — the script the *CSV Exporter for Model Catalog* guide documents.
It is not part of the downloaded RHOAI documentation; download it before continuing.

.Procedure

. Confirm your Python version meets the 3.10+ requirement:
+
[source,bash,role="execute",subs="attributes"]
----
python3 --version
----
+
Expected output:
+
----
Python 3.12.3
----
+
Any Python 3.10 or newer version is sufficient; the script has no additional dependencies.
. Download the export script:
+
[source,bash,role="execute",subs="attributes"]
----
curl -L -o model_catalog_export.py https://raw.githubusercontent.com/kubeflow/model-registry/main/tools/csv-exporter/model_catalog_export.py
----
+
The script uses only the Python standard library, so no `pip install` is required. Confirm it is
runnable:
+
[source,bash,role="execute",subs="attributes"]
----
python3 model_catalog_export.py --help
----
+
Expected output:
+
----
usage: model-catalog-export [-h] --url URL [--output OUTPUT] [--source SOURCE]
                            [--limit LIMIT] [--page-size PAGE_SIZE]
                            [--header HEADERS] [--list-sources]

Export Model Catalog metadata to CSV.
----
. Locate the Model Catalog API route that the script reads from:
+
[source,bash,role="execute",subs="attributes"]
----
oc get route -l app=model-catalog
----
+
Expected output:
+
[subs="attributes"]
----
NAME                 HOST/PORT                                   PATH   SERVICES       PORT       TERMINATION   WILDCARD
model-catalog-https  model-catalog.apps.{openshift_cluster_ingress_domain}             model-catalog  https-api  reencrypt     None
----
+
The `model-catalog-https` route exposes the Model Catalog REST API outside the cluster, reencrypted
through the kube-rbac-proxy sidecar that fronts the `model-catalog` service. If no route is listed,
ask your administrator to check the Model Registry component in your registry namespace.
. Capture the catalog API URL and your API token:
+
[source,bash,role="execute",subs="attributes"]
----
CATALOG_URL="https://$(oc get route -l app=model-catalog -o jsonpath='{.items[0].spec.host}')"
echo "$CATALOG_URL"
----
+
Expected output:
+
----
https://model-catalog.apps.{openshift_cluster_ingress_domain}
----
+
The kube-rbac-proxy in front of the API authenticates your requests, so capture the token that
`oc` uses to talk to the cluster:
+
[source,bash,role="execute",subs="attributes"]
----
oc whoami -t
----
. Run the export using the documented usage pattern:
+
[source,bash,role="execute",subs="attributes"]
----
python3 model_catalog_export.py --url "$CATALOG_URL" --limit 10 --header "Authorization: Bearer $(oc whoami -t)" --output catalog-export.csv
----
+
The script paginates through the catalog result set — 100 models per page by default — so large
catalogs need no extra options. First list the catalog sources the API exposes, then restrict the
export to one of them:
+
[source,bash,role="execute",subs="attributes"]
----
python3 model_catalog_export.py --url "$CATALOG_URL" --list-sources
----
+
Expected output:
+
----
ID                NAME              STATUS
community         Community         available
validated_models   Validated Models  available
----
+
The exact source IDs come from the API. Restrict the export to a single source with `--source`:
+
[source,bash,role="execute",subs="attributes"]
----
python3 model_catalog_export.py --url "$CATALOG_URL" --source community --output catalog-export.csv
----
. Wait for the script to finish. It reports the row and column count on stderr:
+
----
Exported 10 models (18 columns) to catalog-export.csv
----

.Documented script options

|===
|Option |Behavior

|--url |Catalog API base URL the script queries (required)
|--output |Path of the RFC 4180 CSV file to write (required unless you use `--list-sources`)
|--source |Filters the export by catalog source ID; repeat the flag to export multiple sources
|--limit |Limits the number of models included in the output
|--page-size |Number of models fetched per API page (default 100)
|--header |Sets an HTTP header as `Name: Value`; repeat for multiple headers, for example `Authorization: Bearer $(oc whoami -t)`
|--list-sources |Lists the available catalog sources and exits
|===

=== Verify

The script exits without errors and reports `Exported N models (M columns) to <output>` on stderr,
where the row count matches the `--limit` value you set or the full catalog result set when no
limit was given. If the run fails mid-export, no partial CSV file is left behind: the script writes
atomically and only publishes the file once the full result set has been fetched.

With a CSV in hand, validate what the export actually produced.

== Exercise 3: Validate the exported CSV

The export produces an RFC 4180-compliant CSV file that includes all model metadata and custom
properties from the catalog.

.Procedure

. Inspect the first line of the exported file to confirm the header row:
+
[source,bash,role="execute",subs="attributes"]
----
head -n 1 catalog-export.csv
----
+
Expected output:
+
----
id,name,description,provider,maturity,license,licenseLink,libraryName,source_id,externalId,createTimeSinceEpoch,lastUpdateTimeSinceEpoch,language,tasks,validatedTasks,<custom-properties>
----
+
The header covers the standard model metadata columns followed by one column per custom property
(`<custom-properties>` above). The file starts with a UTF-8 BOM that is invisible in terminal
output, and rows are quoted per RFC 4180.
. Count the models in the export and confirm the row count matches the `--limit` value you set,
or the full result set when no limit was given:
+
[source,bash,role="execute",subs="attributes"]
----
tail -n +2 catalog-export.csv | wc -l
----
+
Open the file in a spreadsheet application or CSV viewer and confirm:
* Every row is a model from the catalog result set.
* Each row includes the model metadata you saw on the model details page in Exercise 1, such as
name, description, provider, and labels.
* Custom properties appear as columns alongside the standard model metadata.
. Optional: Re-run the export with `--source` restricted to a single catalog source and confirm
that the output only contains models from that source.

=== Verify

The exported file opens cleanly as RFC 4180-compliant CSV: a header row followed by one row per
model, with all model metadata and custom properties present. Rows respect the `--source` and
`--limit` options you passed to the script, and the header row matches the model metadata columns
you saw in Exercise 1.

* Located the Model Catalog in the OpenShift AI dashboard and identified the metadata it holds
* Ran the standalone Python CSV export script with its documented options
* Validated that the exported file is RFC 4180-compliant CSV containing model metadata and custom properties

**Key takeaways:**

* CSV export packages the full Model Catalog result set — metadata plus custom properties — as RFC 4180-compliant CSV via the Model Catalog REST API
* The export script is standalone Python 3.10+ with no additional dependencies and writes atomically, so failures never leave partial files
* `--url` and `--output` point the script at the catalog API and the CSV file; `--source`, `--limit`, and `--header` control source filtering, output size, and API authentication
