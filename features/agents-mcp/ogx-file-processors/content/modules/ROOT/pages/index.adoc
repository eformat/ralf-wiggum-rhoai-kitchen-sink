The *OGX File Processors API* is a Developer Preview API in RHOAI 3.5 that
converts documents and files into vector-ready chunks using configurable
extraction backends. It is exposed by the OGX server at the
`/v1alpha/file-processors` endpoint and is powered by pluggable providers such
as Docling, MarkItDown, and PyPDF, making it the document-ingestion step of
retrieval-augmented generation (RAG) workflows built on OGX.

**What you will learn:**

* What the File Processors API does, where its `/v1alpha/file-processors` endpoint lives, and what Developer Preview means for it
* Which extraction-backend providers power the API (inline::auto, inline::docling, inline::markitdown, inline::pypdf, remote::docling-serve) and how each is enabled
* How a document flows from upload to vector-ready chunks in a RAG workflow
* Verify the OGX components in your cluster and tour the documented document-processing paths: the OpenAI-compatible Files + Vector Stores flow and the Docling pipeline

== Prerequisites

* RHOAI operator installed
* OGX enabled
* An OpenShift cluster with RHOAI 3.5 installed
