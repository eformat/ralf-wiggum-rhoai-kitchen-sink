This workshop covers the *MaaS deployment/routing path for Distributed Inference
with llm-d* in Red Hat OpenShift AI 3.5. Models deployed for MaaS use the
`LLMInferenceService` architecture and integrate with the MaaS gateway for
subscription-based quota enforcement. Publishing a model creates a
`MaaSModelRef` that registers it with MaaS, and access is granted through
`MaaSSubscription` and `MaaSAuthPolicy` custom resources.

**What you will learn:**

* How MaaS and the llm-d distributed inference path fit together in RHOAI 3.5
* Verify the MaaS custom resources and the llm-d inference gateway on your cluster
* Deploy a model through the dashboard wizard with the *Distributed inference with llm-d* runtime and publish it as MaaS
* Govern access with `MaaSSubscription` and `MaaSAuthPolicy` custom resources
* Call the model through the MaaS gateway with OpenAI-compatible body-based routing and test token rate limits

== Prerequisites

* An OpenShift cluster running version 4.19.9 or later with RHOAI 3.5 installed
* Distributed inference with llm-d enabled by your cluster administrator, including the
  Gateway API with the `openshift-ai-inference` Gateway and authentication for LLM Inference Service
* Models-as-a-Service enabled: `kserve.modelsAsService` set to `Managed` in the DataScienceCluster
  and the MaaS dashboard flags enabled in the OdhDashboardConfig
* `oc` CLI installed and cluster administrator access for the verification and governance steps
