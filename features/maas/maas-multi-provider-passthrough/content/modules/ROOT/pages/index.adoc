This workshop introduces *Multi-provider API passthrough for external models (MaaS)*.

**What you will learn:**

* How the MaaS gateway detects API formats and when passthrough activates instead of translation (`/v1/messages`, `/v1/responses` versus `/v1/chat/completions`)
* Creating the provider API key secret and the `ExternalProvider` custom resource that defines the external endpoint and authentication
* Mapping a client-facing model name to an external provider with an `ExternalModel` custom resource using a passthrough-eligible `apiFormat` (`messages` or `openai-responses`), and publishing it with a `MaaSModelRef`
* Verifying external model routing from the dashboard and testing single-URL passthrough with AI coding tools such as Claude Code

== Prerequisites

* An OpenShift cluster with RHOAI 3.5 installed and Models-as-a-Service deployed
* Cluster administrator privileges for the OpenShift cluster
* At least one MaaS subscription to which you will add the external model
* An external provider API key (for example, an Anthropic API key)
* Recommended prerequisite: complete the xref:maas-core::index.adoc[Models-as-a-Service (MaaS) core: access model and token mechanism] workshop first
