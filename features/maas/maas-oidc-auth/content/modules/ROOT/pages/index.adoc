This workshop introduces *MaaS-specific external OIDC user authentication*.

**What you will learn:**

* How MaaS authenticates external OIDC users with a two-tier flow: OIDC tokens for platform APIs, API keys for model access
* Configure the `AITenant` custom resource with your external OIDC provider's issuer URL, client ID, and signing-key cache TTL
* Create MaaS subscriptions and authorization policies that map external OIDC group claims to model access
* Verify authentication end to end through the MaaS management API with a real OIDC token

== Prerequisites

* An OpenShift cluster with RHOAI 3.5 installed and cluster administrator privileges
* Models-as-a-Service deployed
* An external OIDC provider, such as Keycloak, with a registered client application (issuer URL and client ID)
* User groups defined in the OIDC provider, with group claims included in ID tokens
* Recommended prerequisite: complete the xref:maas-core::index.adoc[Models-as-a-Service (MaaS) core: access model and token mechanism] workshop first
