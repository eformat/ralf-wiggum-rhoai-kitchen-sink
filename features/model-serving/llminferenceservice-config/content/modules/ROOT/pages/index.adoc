This workshop introduces *LLMInferenceService / LLMInferenceServiceConfig (llm-d-native)* —
the declarative CR that replaces `InferenceService` for generative LLM serving, and the
template model that powers the dashboard's llm-d topology selector.

**What you will learn:**

* How `LLMInferenceService` composes model, router, gateway, scheduler, and template configuration in one CR
* Deploying a model with a real `LLMInferenceService` manifest and sending an authenticated chat-completion request
* The four llm-d topology patterns and how `opendatahub.io/config-type` labels drive wizard discovery
* Creating topology and router `LLMInferenceServiceConfig` templates as an administrator, and how `baseRefs` merges them
* Running a disaggregated prefill/decode workload with the `prefill` spec section

== Prerequisites

* An OpenShift cluster with RHOAI 3.5 installed and the model serving platform enabled
* OpenShift 4.19.9 or later, with OpenShift Service Mesh v2 *not* installed
* A `GatewayClass` and `Gateway` named `openshift-ai-inference` in the `openshift-ingress` namespace
* Network access to pull models from Hugging Face, or models in S3/PVC/OCI storage
* Administrator privileges for the topology template exercises in Module 03
