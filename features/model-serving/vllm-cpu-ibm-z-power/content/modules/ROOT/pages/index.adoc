This workshop introduces *vLLM CPU ServingRuntime on IBM Z / Power* — the
*vLLM CPU ServingRuntime for KServe* in RHOAI 3.5, the supported path for serving
models with vLLM on IBM Power (ppc64le) and IBM Z (s390x) clusters. Two constraints
shape everything you will do here: you cannot use GPU accelerators with IBM Z and
IBM Power architectures, and on those architectures you can only deploy models in
standard deployment mode.

**What you will learn:**

* Why the vLLM CPU ServingRuntime for KServe is the supported vLLM runtime on IBM Z (s390x) and IBM Power (ppc64le) in RHOAI 3.5, and what its deployment constraints are
* Check your cluster architecture and locate the pre-installed runtime from the CLI
* Deploy a generative model from the RHOAI dashboard with the *Deploy a model* wizard: model location, hardware profile, CPU/memory resources, and the vLLM CPU runtime
* Verify the deployment from the console and the CLI, then send OpenAI-compatible inference requests with token authentication

== Prerequisites

* An OpenShift cluster running on IBM Z (s390x) or IBM Power (ppc64le) with RHOAI 3.5 installed — RHOAI Self-Managed is supported on both architectures
* KServe installed and the model serving platform enabled
* The vLLM CPU ServingRuntime for KServe enabled in your cluster (it ships pre-installed; your administrator can enable or disable it)
* A project with a connection to your model storage: S3-compatible object storage, a URI-based repository, an OCI-compliant registry, or a persistent volume claim (PVC)
