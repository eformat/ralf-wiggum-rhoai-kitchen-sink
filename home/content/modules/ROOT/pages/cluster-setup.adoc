= Cluster Setup

The workshop labs run on a base RHOAI configuration shipped in this repo at
`cluster/` — plain kustomize overlays: `base` plus fine-grained overlays
(serving, llmd, gpu-config, cpu-config, maas, monitoring, gateway, and the
single-component toggles). OpenShift itself is a prerequisite; this configures
**RHOAI only**.

Every overlay includes `base`, so `oc apply -k cluster/overlays/<x>` applies
base + that overlay in one shot and stacking overlays is cumulative and
idempotent. `cluster/feature-overlays.yml` is the machine-readable
feature → overlay map.

== Quick start (full kitchen-sink cluster)

[source,bash,role="execute"]
----
oc apply --server-side --force-conflicts --field-manager=kustomize-base -k cluster/base
make -C cluster wait-csv NS=redhat-ods-operator PREFIX=rhods-operator
make -C cluster dashboard-flags

oc apply --server-side --force-conflicts --field-manager=kustomize-gpu-config -k cluster/overlays/gpu-config   # or cpu-config for a GPU-less cluster
make -C cluster wait-csv NS=openshift-nfd PREFIX=nfd
oc apply -k cluster/overlays/gpu-config/activation

oc apply --server-side --force-conflicts --field-manager=kustomize-serving -k cluster/overlays/serving

export CLUSTER_DOMAIN=$(oc get ingress.config cluster -o jsonpath='{.spec.domain}')
oc kustomize cluster/overlays/llmd | envsubst '${CLUSTER_DOMAIN}' | oc apply --server-side --force-conflicts --field-manager=kustomize-llmd -f -
make -C cluster wait-csv NS=openshift-lws-operator PREFIX=leader-worker-set
make -C cluster wait-csv NS=openshift-jobset-operator PREFIX=jobset
oc apply -k cluster/overlays/llmd/activation

oc apply --server-side --force-conflicts --field-manager=kustomize-gateway -k cluster/overlays/gateway
make -C cluster wait-csv NS=openshift-operators PREFIX=rhcl
oc apply -k cluster/overlays/gateway/activation

oc apply --server-side --force-conflicts --field-manager=kustomize-monitoring -k cluster/overlays/monitoring

make -C cluster maas-secrets
oc kustomize cluster/overlays/maas | envsubst '${CLUSTER_DOMAIN}' | oc apply --server-side --force-conflicts --field-manager=kustomize-maas -f -
# no-LB clusters (RHDP/bare-metal): make -C cluster gateway-status

for o in trustyai ogx mcp registry mlflow feature-store distributed; do
  oc apply --server-side --force-conflicts --field-manager=kustomize-$o -k cluster/overlays/$o
done

make -C cluster cluster-verify
----

*Why server-side apply* — overlays patch the same DataScienceCluster resource;
client-side `oc apply` prunes components set by previously-applied overlays
(last-write-wins on `spec.components`). Each overlay's distinct
`--field-manager` makes it own only its component keys. *Two-step overlays*
(`gpu-config`, `llmd`, `gateway`) ship activation CRs applied only after their
operator CSVs reach Succeeded — the `wait-csv` steps above handle that. The
full flow, ordering constraints, and prerequisites are documented in
`cluster/README.md`.

== Which overlays does each lab need?

Every lab needs `cluster/base` plus the overlays listed below. Single-lab
setup: open the collapsible block for that lab below and run it — it applies
base, the lab's overlays in dependency order (including two-step activation
waits, MaaS secrets, and `${CLUSTER_DOMAIN}` rendering), and finishes with
`make -C cluster cluster-verify`. Blocks are generated from
`cluster/feature-overlays.yml` — edit that file and run
`make -C cluster lab-blocks` to update them.


|===
|Overlay |What it provides

|base
|rhods-operator install + core DSC (dashboard, workbenches, pipelines) + all dashboard flags

|serving
|KServe model-serving platform (RawDeployment, no Service Mesh)

|llmd
|openshift-ai-inference Gateway + JobSet/LWS serving-path operators

|gpu-config / cpu-config
|GPU variant (NFD + AcceleratorProfile) / CPU-only variant (vLLM CPU runtime)

|gateway
|cert-manager + RHCL/Kuadrant (Gateway API control plane)

|monitoring
|User Workload Monitoring + Cluster Observability + OpenTelemetry

|maas
|MaaS flip (aigateway.modelsAsAService) + PostgreSQL + maas-default-gateway

|trustyai / ogx / mcp / registry / mlflow / feature-store
|single DSC component toggles

|distributed
|Ray + Kueue (RHBoK ≤1.3) + Kubeflow Trainer + Training Operator

|oidc
|base-only no-op (OCP direct-OIDC is install-time config; the GatewayConfig patch is a lab exercise)
|===

== Verify

[source,bash,role="execute"]
----
make -C cluster cluster-verify
----

Checks operator CSVs, DSC/DSCI Ready, dashboard flags, Gateways `PROGRAMMED`,
the MaaS tenant `READY`, and every component state the labs assume. Checks
auto-skip for overlays that were not applied.
