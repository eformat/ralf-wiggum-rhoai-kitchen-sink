# Observations: External Metering Integration for MaaS (doc-derived)

## Summary

External metering integration for MaaS is a RHOAI 3.5 Developer Preview feature
that connects Models-as-a-Service (MaaS) inference traffic to an external
metering or billing system using Backend-Based Routing (BBR) plugins. This
observation document was produced from the official RHOAI 3.5 product
documentation (release notes available-assets section; Govern LLM access with
Models-as-a-Service) because no live demo cluster was available at authoring
time. Every item below is doc evidence, not UI evidence.

## User Flows

### Flow 1: Metered inference request on a MaaS gateway

1. **Prerequisites** — model published as MaaS (MaaSModelRef), subscription with token quota (MaaSSubscription), gateway access (MaaSAuthPolicy)
2. **Pre-inference credit check** — BBR request plugin asks the external metering system for credit; exhausted credit blocks the next request before model compute is spent
3. **Inference** — model processes the request
4. **Post-inference webhook** — BBR response plugin asynchronously emits a structured token usage event (requester, subscription, model, token counts, request ID, timestamp) to the configured external metering endpoint
5. **External accounting** — invoice generation, cost attribution, and rate calculation happen in the external system

### Flow 2: Operator enables metering on a gateway

1. **Per-gateway configuration** — plugins are activated and deactivated per-gateway through configuration
2. **Scope** — applies to internal model inference and external model requests
3. **Recovery** — failed webhook delivery attempts are logged for alerting and recovery

## Features and Concepts

### OpenShift Platform
- API gateway, gateway policies (AuthPolicy, TokenRateLimitPolicy generated by the MaaS controller), RBAC

### RHOAI / AI Platform
- MaaS governance layer (MaaSModelRef, MaaSSubscription, MaaSAuthPolicy), BBR plugin chain (response plugin for usage events, request plugin for credit checks), per-gateway plugin activation; sibling per-user external metering IPP plugin + PostgreSQL-backed standalone metering service; MaaS observability dashboard for showback

### AI/ML Fundamentals
- Token accounting (input/output token counts per request), commercial AI service billing and chargeback vs showback

## Workshop Potential

- **Estimated modules**: 2 (getting started → hands-on)
- **Target audience**: platform operators running MaaS as a commercial AI service
- **Prerequisite knowledge**: MaaS governance layer, `oc` CLI basics
- **Estimated duration**: 45–60 minutes
- **Cluster requirements**: RHOAI 3.5 with MaaS enabled and at least one published model, subscription, and authorization policy
